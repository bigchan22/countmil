\section{Experiments}
\label{sec:experiments}

\subsection{Experimental setup}

We evaluate finite-support aggregation under five aggregate-label themes:
\begin{enumerate}
  \item ordinal integer-valued sum labels;
  \item signed count labels with cancellation;
  \item Bernoulli count labels as a recovery of prior count loss;
  \item class-count and histogram labels connecting to LLP;
  \item runtime of exact aggregate backends.
\end{enumerate}
Unless otherwise stated, MNIST-family experiments use LeNet-style instance networks, bags are sampled on the fly, and tables report means over three random seeds.
Hidden instance labels are never used for training; they are used only for evaluation.
Implementation details are summarized in Appendix~\ref{app:implementation-details}.
Each subsection changes the observed aggregate label while keeping the same finite-support convolutional likelihood interface.

\paragraph{Metrics.}
Across the experimental tables, aggregate MAE columns report the mean absolute difference between the predicted aggregate and the observed aggregate over test bags.
For expected-value baselines, the predicted aggregate is the scalar expectation trained by the baseline.
For exact-likelihood rows, the prediction rule uses the aggregate PMF statistic specified by the corresponding table: count, integer-valued sum, signed count, or histogram count.
For histograms, count MAE is the mean absolute class-count error averaged over classes and bags,
\begin{equation}
  \frac{1}{N}\sum_{B}\frac{1}{C}\sum_{c=1}^C |\hat{h}_{Bc}-h_{Bc}|.
\end{equation}
Rows labelled MSE denote MSE training objectives; MAE and accuracy columns are evaluation metrics computed after training.
Columns labelled instance accuracy use held-out instance labels only for evaluation, never for training.
Instance accuracy is never used for model selection unless explicitly stated.

\subsection{Ordinal sum labels}

Digit-sum supervision is an integer-valued aggregate label: the learner observes a single scalar while each hidden instance label has ten possible values.
Here $z_i$ is the original MNIST digit value in $\{0,\ldots,9\}$ and the bag label is $Y_{\rm sum}=\sum_i z_i$.
Exact finite-support likelihood uses the full induced distribution over possible sums, whereas an expected-value baseline regresses only $\sum_i \mathbb{E}[z_i]$ to the observed sum.

On SVHN with $5000$ bags, the pretrained exact-likelihood model reaches $95.46\%$ hidden digit accuracy and $65.00\%$ exact sum accuracy, while the pretrained MSE baseline reaches $82.58\%$ hidden digit accuracy and $22.58\%$ exact sum accuracy.
UltraMNIST gives a controlled patch-based benchmark with high hidden digit recovery.

\subsection{Signed aggregates with cancellation}

Signed counts test an aggregate that is not reducible to ordinary class proportions.
We again use the digit-$9$ target indicator, but each instance carries a known random sign; target-digit images contribute $+1$ or $-1$, while all other digits contribute $0$.
Even with random signs, the observed signed sum is many-to-one: positive and negative contributions can cancel, so different latent assignments can yield the same bag label.
The exact likelihood nevertheless yields lower signed-count error than a simple expected-signed-sum MSE baseline.

The CIFAR-10 pretrained probes further show that signed finite-support aggregation can recover target-class detectors in a harder natural-image setting, reaching instance AUCs of $98.23\%$ for $n=16$ and $99.19\%$ for $n=64$.
This setting is a direct example of why finite-support aggregation is not only a reformulation of ordinary nonnegative counts: cancellation changes the inverse problem even when the hidden instance variable remains Bernoulli.

\subsection{Recovery of Bernoulli count loss}

Binary Count-MIL validates the connection to prior count-loss work.
For MNIST-Bags, we make MNIST binary by choosing digit $9$ as the positive class and treating digits $0$--$8$ as negative.
The learner observes the number of target-digit images in the bag; hidden instance labels are used only for evaluation.
This case verifies that the convolutional formulation recovers the established Bernoulli count probability while sharing the same implementation pattern as the new aggregate types.

\subsection{Class histograms and LLP connections}

Histogram supervision is included mainly to connect the proposed finite-support view to recent LLP-PVC work.
For MNIST histograms, the hidden category is the original digit class and the observed label is the vector of digit counts in the bag.
We evaluate the classwise one-vs-rest count likelihood (OVR count), which corresponds to the Bernoulli count-likelihood component of LLP-PVC, rather than a full joint multiclass histogram likelihood.
The comparison here is deliberately simple: MSE matches expected class counts, while OVR count scores the observed count with the exact classwise count PMF.

On the representative MNIST large-bag setting, OVR count likelihood improves over MSE proportion matching in count MAE and hidden digit accuracy; the omitted smaller-bag rows follow the same pattern.
This supports the connection to class-count LLP objectives without making the histogram setting the main novelty claim.
The CIFAR-10 rows are narrower: they show that OVR count likelihood is effective with ImageNet-pretrained ResNet-18 features and that it substantially outperforms a simple pretrained MSE histogram baseline at $n=16$ and $n=64$.
However, the $n=64$, train $1000$ setting exposes four times as many image instances per epoch as $n=16$, train $1000$.
The fixed-instance-budget setting, $n=64$ with $250$ train bags, reaches only about $80.3\%$ final instance accuracy and $80.6\%$ when selecting by observed histogram MAE.
Thus the CIFAR-10 results should be read as evidence that count likelihood can use aggregate-labeled image volume effectively under a strong representation, not as evidence that larger bags are intrinsically superior.

\subsection{Backend runtime}

Our FFT-tree backend computes batched multiclass one-vs-rest count PMFs on GPU and gives large practical speedups over CPU dynamic programming in large-bag benchmarks.
This addresses a practical limitation of DP-based count losses: exact count probabilities need not be tied to a sequential CPU implementation.
The benchmark isolates aggregate-PMF evaluation; it measures backend speed rather than end-to-end training time or representation quality.
